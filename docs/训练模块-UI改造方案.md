# 训练模块 · UI 与交互改造方案（科学版）

> 目标：把「今日安排 + 打卡」升级成「一次训练 = 一个 session」的训练系统；
> 记录不超过 3 次点击/组，练完能回答：今天练了什么、够不够、下次加多少。

---

## 一、现状诊断（基于实际页面）

当前 `training.html` 是「今日安排」而不是训练工具：

- 顶部「本周计划」7 个彩色小胶囊，信息密度低，只能看出力量/有氧，看不出练什么；
- 主卡片是「今日训练」，但只有一个动作 + 热身，记录要打开底部 sheet；
- 没有「开始/结束训练」，没有总时长；
- 「计划 / 追踪」只是两个入口卡，真正的数据在另外两个页面；
- 底部 5 个 tab（今日安排/目标/习惯/回顾/我的）与壳的 tab 重复；
- 训练中最重要的信息（上次重量、RPE、休息）都不在首屏。

**结论**：不是视觉问题，是信息架构问题——页面按「日程」组织，而不是按「训练」组织。

---

## 二、设计原则

1. **一次训练一个 session**：开始 → 记组 → 结束，时长只记一次。
2. **默认值来自上次**：重量、次数、RPE 预填上次成绩，用户只改变化。
3. **一屏一个决策**：今日只回答「练什么、开始」；训练中只回答「这一组」。
4. **科学指标可见但不堆砌**：周有效组数、e1RM、容量趋势放在进度页。
5. **30 秒单手**：组行 44px 高，数字键盘/步进器，休息计时自动开始。
6. **不重复导航**：模块内用「今日 / 进度 / 计划」三段，不再放第二套底部 tab。

---

## 三、新信息架构

```
训练
├─ 今日（默认）
│   ├─ 本周进度 3/4
│   ├─ 今天练什么（建议 + 开始）
│   ├─ 快速开始（推/拉/腿/有氧/重复上次）
│   ├─ 本周肌群（有效组数）
│   └─ 最近训练
├─ 进度
│   ├─ 周/月切换
│   ├─ 容量趋势 / e1RM（深蹲·卧推·硬拉）
│   ├─ 每肌群周组数 vs MEV/MAV
│   └─ 依从率日历 + PR 墙
└─ 计划
    ├─ 周模板（周一推 / 周二拉 / 周四腿…）
    ├─ 每个训练日的动作、目标组×次
    └─ 容量检查（低于 MEV / 超过 MRV 提示）
```

训练中与总结是全屏层，不占 tab。

## 四、页面规格

### 1. 今日（首屏）

```
┌─────────────────────────────┐
│ 训练                  ⚙︎     │
│ 本周 3/4 次       连续 6 周  │
│ ┌─────────────────────────┐ │
│ │ 今天：推 A              │ │
│ │ 45 分钟 · 胸 / 肩 / 三头 │ │
│ │ 上次 3 天前 · 状态良好   │ │
│ │ [ 开始训练 ]   [换一个]  │ │
│ └─────────────────────────┘ │
│ 快速开始                    │
│ [推] [拉] [腿] [有氧] [上次]│
│ 本周肌群                    │
│ 胸 12 · 背 10 · 腿 8 · 肩 6 │
│ 最近                        │
│ 10/19 拉 B · 48min · 8,200kg│
└─────────────────────────────┘
```

- 「今天」由计划 + 最近 48h 决定；没有计划时推荐「重复上次」；
- 容量条用 3 段色：<MEV 灰、MEV–MAV 绿、>MRV 红；
- 热身折叠成一行「热身 5 分钟」，不再占主卡。

### 2. 训练中（全屏）

```
┌─────────────────────────────┐
│ ← 推 A          00:42:13 结束│
│ 深蹲            上次 80×5@8  │
│ 组   kg    reps   RPE   ✓   │
│ 1   [80]  [5]    [8]   ✓   │
│ 2   [80]  [5]    [9]   ✓   │
│ + 加一组                    │
│ ┌ 休息 02:30  [跳过] ┐      │
│ 下一个：卧推 60×8            │
│ [ 完成训练 ]                │
└─────────────────────────────┘
```

- 每行 44px；kg/reps 用步进器（±2.5 / ±1），长按连续；
- RPE 用 4 个 chip：6/7/8/9/10（默认上次）；
- 完成一组自动开始休息计时（按动作类型默认 90/150/180 秒）；
- 顶部计时从「开始训练」起算，切后台不丢（存 startedAt）。

### 3. 训练总结

```
推 A · 52 分钟
总容量 9,840 kg · 18 组 · 4 个动作
胸 9 组 · 肩 6 组 · 三头 3 组
PR：卧推 62.5kg × 8（e1RM 78）
[ 保存 ] [ 补备注 ]
```

保存时只写一条 `运动 minutes=52`；容量/组数进 session。

### 4. 进度

- 周/月切换；
- 容量柱状 + 4 周均线；
- e1RM 折线（深蹲/卧推/硬拉切换）；
- 肌群周组数横向条，标 MEV/MAV/MRV 三条刻度；
- 依从率日历：练了=实心，休息=空心，漏=灰；
- PR 墙：动作 + 重量×次数 + 日期。

### 5. 计划

- 周模板：7 天卡片，每天选「推/拉/腿/有氧/休息」；
- 点某天 → 编辑动作：动作库搜索、目标组×次、备注；
- 底部实时容量检查：`胸 14 组（MAV）`、`腿 6 组（低于 MEV）`；
- 提供 3 套模板：推拉腿、上下肢、全身 3 日。

## 五、数据模型

```json
{
  "v": 2,
  "sessions": [{
    "id": "s_...",
    "date": "2026-10-21",
    "kind": "strength",
    "startedAt": 1792...,
    "endedAt": 1792...,
    "durationMin": 52,
    "sessionRpe": 8,
    "exercises": [{
      "name": "深蹲", "muscle": "legs",
      "sets": [{ "weight": 80, "reps": 5, "rpe": 8, "restSec": 150 }]
    }],
    "cardio": null,
    "notes": ""
  }]
}
```

派生：

- volume = Σ(weight×reps)
- e1RM = weight×(1+reps/30)
- hardSet = RPE≥7 且 5≤reps≤30
- weeklySets[muscle] = 本周 hardSet 数
- adherence = 完成 session / 计划 session

旧 `lifeflow-train-records` 迁移：按日期 + 时间邻近归组，幂等；旧记录只读。

## 六、建议引擎（规则透明）

| 条件 | 建议 |
|---|---|
| 所有组达次数上限且 RPE≤8 | 下次 +2.5kg（上肢）/ +5kg（下肢） |
| 连续 2 次未达下限，或 RPE≥9.5 | 重量 −10% 或减一组 |
| 连续 3 次 RPE≥9，或 4–6 周未 deload | 建议 deload：容量 −40%，强度 −10% |
| 某肌群周组数 <MEV | 下次加 1–2 组 |
| 某肌群 >MRV 且酸痛 | 减 2 组或延后 |
| 准备度 ≤2 | 本次容量 −20% |

所有建议只展示「建议」，不自动改计划；用户点「采用」才写入。

---

## 七、视觉规范

- 保留 v3 暖纸/墨色；训练强调色用现有朱红 `#A0342C`，只用于 CTA 和 PR；
- 数字用等宽/tabular，重量 28–32px，组行 44px；
- 卡片圆角 18，阴影克制；进度条 6px；
- 动效：完成一组轻微对勾 + 触感（如支持）；休息计时呼吸；
- 空状态：没有计划时给「生成 3 日全身计划」；没有记录时给「记第一次」。

## 八、分阶段实施

### P0（2–3 天）：先能正确记录

- `core/training.js`：session CRUD、volume、e1rm、weeklySets、迁移；
- 训练页加「开始训练 / 结束训练」；时长只写一次；
- 保留现有动作记录 sheet，但写入 session；
- 删除每动作 +10 分钟的假 LightStore 记录。

### P1（3–4 天）：新 UI 骨架

- 今日页重做（今天卡、快速开始、本周肌群、最近）；
- 训练中全屏（组行、RPE、休息计时、上次成绩）；
- 总结页；
- 去掉重复底部 nav，改三段切换。

### P2（3–5 天）：进度与计划

- 进度页（容量、e1RM、肌群组数、依从率、PR）；
- 计划页（周模板、动作库、容量检查、3 套模板）；
- 准备度、deload 建议。

### 测试

- 纯函数：迁移幂等、容量、e1RM、周组数、PR、建议规则；
- 浏览器：开始→记组→结束→只写 1 条分钟；刷新恢复进行中训练；RPE/休息；进度数字；
- 回归：旧 records 不影响新统计。

## 九、不做什么

- 不做社交/排行榜/课程视频；
- 不做 HealthKit/手表（无后端、权限复杂）；
- 不在 P0 做复杂周期化；
- 不重写三个页面；先共享 `training.js`，页面逐步替换。
